# РГР. Спільний проєкт: завдання для другого виконавця (Аніщенко А.)

Документ підсумовує, що має зробити другий учасник спільного проєкту з дисципліни
«Основи розробки трансляторів». Складено за: завданням на РГР (розд. 3, п. 3), силабусом
дисципліни, графіком освітніх активностей та посібником Стативки Ю. І. (розд. 2.4).

**Спільний проєкт:** одна мова програмування — **Krok** (мова-прототип — **Go**, Рівень 2 «Основний»).
Виконавці: Степаненко Н. Ю., Аніщенко А. О.

За умовою завдання спільний проєкт означає, що:

- кожен виконавець обирає **власний варіант інструкцій повторення та розгалуження**;
- кожен подає **власну специфікацію**;
- кожен **особисто захищає** роботу.

Решта мови (алфавіт, лексика, типи, вирази, функції, масиви, структури) — спільна.

## 1. Обрати власні варіанти інструкцій

Варіанти мають відрізнятися від уже зайнятих.

| Виконавець | Інструкція повторення | Інструкція розгалуження |
|---|---|---|
| Степаненко Н. Ю. | `for` з передумовою + трикомпонентний `for` | `if / else if / else` |
| Аніщенко А. О. (пропозиція) | `for { ... }` з `break` / `continue` | `switch` з гілками `case` і `default` |

## 2. Написати власну специфікацію

Структура — за розд. 2.4 посібника [1], як цього вимагає завдання:

1. **Вступ** — назва мови та мотивація назви, рівень складності, мова-прототип, призначення;
   окремим підрозділом — опис використаної версії РБНФ **та способу опису семантики**.
2. **Лексична структура** — алфавіт, роздільники рядків, пробільні символи, коментарі,
   ідентифікатори, ключові слова, літерали, оператори; **таблиця токенів обов'язкова**.
3. **Типи даних і змінні** — базові, користувацькі, сконструйовані типи; приведення типів.
4. **Вирази** — класифікація, порядок обчислення, таблиця пріоритетів і асоціативності.
5. **Інструкції** — тут описуються **власні** `switch` і `for`.
6. **Декларації** — змінні, іменовані константи, типи, функції, області видимості.
7. **Структура програми** — файл, пакет, імпорт, функція `main`, помилки.
8. **Приклади програм** — контрольні приклади всіх конструкцій та обов'язковий
   **«Базовий приклад»**: програма, у якій зустрічаються приклади **всіх** лексем із таблиці токенів.
9. **Повна граматика мови** — обов'язково **в останньому розділі**, у порядку від `Program`
   до низькорівневих конструкцій `Letter` і `Digit`.

Синтаксичні діаграми Вірта мають бути **згенеровані за граматикою** (вручну малювати не можна).

## 3. Технічні вимоги до граматики

- граматика має лишатися **LL(1)**: без лівої рекурсії, без конфліктів FIRST/FIRST та FIRST/FOLLOW;
- найризикованіше місце — `switch`: слід чітко визначити списки `case`, гілку `default`,
  наявність або відсутність «провалу» (fallthrough) і місця, де дозволений `break`;
- у таблицю токенів додаються нові ключові слова: `switch`, `case`, `default`, `break`, `continue`;
- базовий приклад після цього має покривати й ці нові лексеми.

## 4. Організаційні пункти

- перевірити, що **обидва** виконавці записані в таблиці «Список мов-прототипів. Група ТВ-43»
  (Go, спільний проєкт — «так»);
- здати **5 етапів** за графіком: тижні **3, 6, 8, 10, 12**; **захист — 14-й тиждень**;
- бали за Рівень 2: **12** (10 — виконання п'яти етапів, 2 — представлення фінальної версії);
- без зданої РГР **немає допуску до екзамену** (разом із КП 1, 2, 3 і 4 або 5).

## 5. Зв'язок із комп'ютерним практикумом

Роботи КП 1–6 (лексичний аналізатор → синтаксичний аналізатор → семантичний аналізатор →
трансляція у ПОЛІЗ → трансляція для CLR/JVM → ANTLR4) реалізують **власний варіант мови**.
На захисті РГР (практичні заняття 25–26) потрібно продемонструвати, що реалізація мови (КП 5)
**відповідає її специфікації**. Отже, специфікація є технічним завданням на весь семестр.

## 6. Що можна взяти готового

Інструментарій у цій папці працює з одного файлу граматики, тож достатньо замінити правила
інструкцій на власні та перезапустити скрипти — діаграми, таблиця токенів і документ
згенеруються автоматично.

| Файл | Призначення |
|---|---|
| `grammar/krok.ebnf` | граматика мови — єдине джерело для діаграм і тексту специфікації |
| `tools/check_grammar.py` | перевірка: контекстна вільність, марні символи, ліва рекурсія, цикли, LL(1), алфавіт |
| `tools/krok_parse.py` | лексер і парсер: розбір прикладів, перевірка покриття таблиці токенів |
| `tools/gen_diagrams.py` | генерація діаграм Вірта з граматики |
| `tools/export_visualizer.py` | експорт граматики для EBNF Visualizer, EBNF 2 RailRoad, Railroad Diagram Generator |
| `tools/build_spec.py`, `tools/finalize.ps1` | збирання специфікації у DOCX і PDF |
| `CHECKLIST.md` | повний перелік вимог з усіх матеріалів курсу (100 пунктів) |

Порядок роботи:

```sh
python tools/check_grammar.py                                 # граматика: 9 перевірок
python tools/krok_parse.py --coverage examples/*.krok         # приклади й покриття токенів
python tools/gen_diagrams.py                                  # діаграми Вірта
python tools/build_spec.py                                    # -> DOCX
pwsh tools/finalize.ps1                                       # зміст у Word + PDF
```
